# ТЗ: ESP32-шлюз BMZ 618031 → Easun SMH III 6.2kW

> Копия ТЗ из Claude Docs (https://claude.ai/artifact/Lvc7wf4wDpy2pV5D6DLPxw), снята 2026-10-21. Актуальная версия — по ссылке.
2026-10-15 · @Ди
## 1. Назначение и цель
Нужно разработать шлюз на ESP32, который читает данные встроенной BMS модуля BMZ 618031 и передаёт их инвертору Easun ISolar SMH III 6.2kW по протоколу Pylontech RS485. Инвертор должен видеть «литиевую батарею с BMS», заряжать и разряжать её по лимитам BMS, а не только по порогам напряжения.
Результат проекта:
- прошивка ESP32 с открытым исходным кодом на ESP-IDF (C/C++);
- схема и печатная плата (или макет на модулях) с гальванической развязкой интерфейсов;
- документ с расшифровкой протокола BMZ, полученной реверсом;
- инструкция по подключению и настройке инвертора.
Вне рамок: изменение прошивки инвертора и BMS, параллельная работа нескольких инверторов.
## 2. Исходные данные
Со стороны инвертора всё известно: он принимает только протокол Pylontech по RS485. Со стороны батареи протокол BMZ неизвестен, и это главный риск проекта.

По данным EVcell, 2500 Вт·ч на этикетке — это энергия в ограниченном рабочем окне, а полная ёмкость в диапазоне 2,5–3,65 В на ячейку около 2949 Вт·ч. Там же сказано, что штатная BMS с инверторами не работает. Продавцы на OLX упоминают «CAN/RS485 в зависимости от конфигурации» и возможную потребность во внешней Master BMS. ### 2.3 Ограничение по току
Один модуль даёт до 28,8 А, то есть около 1,4 кВт. Нагрузка 6,2 кВт требует примерно 130 А с шины 48 В. Для полной мощности нужно 5 модулей в параллель, а шлюз должен передавать инвертору DCL и CCL как сумму по модулям.
## 3. Архитектура и аппаратная часть
Шлюз — это ESP32 с двумя гальванически развязанными интерфейсами. Первый читает батарею, второй отвечает инвертору как батарея Pylontech.

| Терминатор CAN | 120 Ом на перемычке | ставится, если шлюз на конце шины |

### 3.2 Распиновки
| Порт | Контакт | Сигнал | Статус |
|---|---|---|---|
| Easun, порт BMS (RJ45) | 1 / 2 / 8 | RS485 A / B / GND | по форуму, A и B проверить |

Как найти сигналы на X1: прозвонить, какие контакты X1 и X2 соединены напрямую (сквозная шина). Затем измерить напряжения относительно минуса батареи. CAN в покое даёт около 2,5 В на обеих линиях, у RS485 между A и B видна разность. Для сравнения: у Pylontech RS485 на контактах 7 и 8 ([python-pylontech](https://github.com/Frankkkkk/python-pylontech)), а у многих инверторов CAN на 4 (H) и 5 (L) ([SolarAssistant](https://origin.solar-assistant.io/help/inverters/deye/SG05LP1/2-in-1-bms-port?locale=de)).
## 4. Протоколы
Сторону инвертора можно писать сразу по спецификации Pylontech RS485. Сторона батареи начинается с реверса, и от его результата зависит весь проект.
### 4.1 Сторона батареи: реверс протокола BMZ
Официальной документации на протокол модуля 618031 и готового реверса нет. Есть рабочая гипотеза, которую этап 1 проверяет первой.
**Гипотеза А: модуль из семейства BMZ ELIOS / ESS.** По даташиту ELIOS совпадают ячейки 26650, 51,2 В, около 2,8 кВт·ч, ток 30 А, встроенная BMS с CAN ([BMZ ELIOS](https://cdn.enfsolar.com/z/pp/2023/3/22lfmcabn3f385ab25/Data-Sheet-Elios-EN-202204.pdf)). Батареи BMZ ESS официально работают с Victron по профилю «CAN-bus BMS» 500 кбит/с, кабель Type B (у батареи CAN-H — контакт 4, CAN-L — 5). GX-устройство Victron шлёт батарее keep-alive; без него батарея через 10 с уходит в ошибку и отключается ([Victron & BMZ](https://www.victronenergy.com/live/battery_compatibility:bmz_ess)). Venus OS определяет BMZ_ESS по стандартным кадрам ([venus #831](https://github.com/victronenergy/venus/issues/831)), то есть ожидаются ID 0x351, 0x355, 0x356, 0x35A, 0x35E и др.
Если гипотеза подтвердится, реверс сводится к проверке масштабов, а шлюз становится мастером: шлёт keep-alive (вероятно, 0x305, как у инверторов Pylontech/Victron) и читает готовые лимиты CCL/DCL. Проверка — сниффером на ESP-IDF из комплекта (500 кбит/с в обычном режиме с ACK, keep-alive по кнопке).
**Гипотеза Б: собственный протокол.** Тогда действует порядок реверса ниже. Для справки: в электробайках BMZ использует CAN 250 кбит/с с ID батареи 0x40X ([Hackaday](https://hackaday.io/project/196158-pedelec-can-hacking-brosebmz)).
Порядок реверса:
1. Пассивное прослушивание X1 в режиме listen-only. CAN: 125 / 250 / 500 / 1000 кбит/с, стандартные и расширенные ID. RS485: 9600 / 19200 / 115200 бод, поиск кадров Modbus RTU или ASCII-кадров, начинающихся с «~».
2. Если модуль вещает сам: записать лог 10–30 минут в покое, под зарядом и под разрядом с известным током. По изменениям байтов найти напряжение, ток, SOC, температуры и напряжения ячеек.
3. Если модуль молчит: он ждёт опроса от мастера. Тогда нужен лог обмена с оригинальным мастером (если удастся найти систему, из которой эти модули) или перебор типовых запросов (Pylontech CID2 0x42, Modbus 0x03). Если и это не сработает — план Б из раздела 8.
4. Проверить, нужен ли «heartbeat» от мастера, чтобы модуль включил силовые ключи. Признак: на силовом разъёме 0 В без связи.
5. Оформить карту кадров в формате DBC (для CAN) или таблицы регистров и сверить её с показаниями мультиметра и токовых клещей.
Рабочие инструменты: скетч-сниффер на ESP32, SavvyCAN с адаптером slcan, USB-RS485 и логический анализатор.
### 4.2 Сторона инвертора: Pylontech RS485
Инвертор — ведущий, шлюз — ведомый: инвертор шлёт запрос, шлюз отвечает. Параметры линии: 9600 бод, 8N1.
Формат кадра (все поля, кроме SOI и EOI, передаются ASCII-символами в hex):
| Поле | Размер | Значение |
|---|---|---|
| SOI | 1 байт | 0x7E «~» |
| VER | 2 символа | версия протокола, обычно 0x20 |
| ADR | 2 символа | адрес батареи |
| CID1 | 2 символа | 0x46 (батарея LFP) |
| CID2 | 2 символа | команда в запросе, код возврата в ответе (0x00 — норма) |
| LENGTH | 4 символа | 4 бита LCHKSUM + 12 бит LENID (число символов INFO) |
| INFO | LENID символов | данные команды |
| CHKSUM | 4 символа | контрольная сумма кадра |
| EOI | 1 байт | 0x0D |
Контрольные суммы: CHKSUM — сумма кодов всех символов между SOI и CHKSUM по модулю 65536, затем инверсия и +1. LCHKSUM — сумма трёх полубайтов LENID по модулю 16, затем инверсия и +1. Пример запроса из спецификации: `~20024642E00202FD33` + CR ([PowerForum](https://powerforum.co.za/topic/3429-pylontech-vs-raspberry-arduino-plc/)). Описание полей совпадает с документом Gobel Power ([GitHub](https://github.com/fancyui/Gobel-Power-RN-BMS-RS485-ModBus)) и кодом [python-pylontech](https://github.com/Frankkkkk/python-pylontech/blob/master/pylontech/pylontech.py).
Команды, которые должен поддерживать шлюз:
| CID2 | Назначение | Обязательность |
|---|---|---|
| 0x4F | версия протокола | обязательно |
| 0x51 | производитель, модель, версия ПО | обязательно |
| 0x42 | аналоговые данные: ячейки, температуры, ток, напряжение, ёмкость, циклы | обязательно |
| 0x44 | аварии и предупреждения | обязательно |
| 0x47 | системные параметры: пороги напряжений и токов | обязательно |
| 0x92 | управление зарядом: лимиты напряжения и тока, флаги разрешений | обязательно |
| 0x93 | серийный номер | желательно |
| 0x60–0x63 | «системные» команды новых версий протокола | по логу инвертора |
Точный список команд, которые опрашивает SMH III, зафиксировать логом на этапе 2. Единицы и масштабы (мВ, 10 мА, 0,1 А, 0,1 К) сверить с оригинальной спецификацией Pylontech RS485 V3.3 / V3.5. На форуме уже был случай с Easun SMG-III: связь есть, значок Li горит, а заряда нет из-за ошибок в единицах и контрольной сумме длины ([PowerForum](https://powerforum.co.za/topic/33314-jk-bms-to-easunisolar-smg-iii-62kw/)).
Минимальная рабочая реализация есть в [diyBMSv4ESP32](https://github.com/stuartpittaway/diyBMSv4ESP32/blob/master/ESPController/src/pylon_rs485.cpp) (код на ESP-IDF UART API): отвечает только на 0x4F, 0x42 и 0x92, VER = 0x28 (2.8), ADR = 0x02, 9600 бод. Важное наблюдение автора: его инвертор не читал аварии 0x44, поэтому запрет заряда и разряда передаётся флагами в ответе 0x92 (бит 7 — заряд разрешён, бит 6 — разряд разрешён). Наш шлюз должен делать так же и не полагаться на 0x44. Там же реализованы CAN-профили Pylontech и Victron с учётом входящего keep-alive 0x305.
### 4.3 Маппинг данных
| Поле Pylontech | Откуда берётся | Правило |
|---|---|---|
| Напряжение батареи | BMZ, напряжение пакета | среднее по модулям |
| Ток | BMZ, ток пакета | сумма по модулям, знак: заряд «+» |
| SOC / SOH | BMZ или расчёт шлюза | если BMZ не отдаёт SOC — кулон-счётчик + калибровка по 100 % |
| Напряжения ячеек | BMZ | 16 значений на модуль |
| Температуры | BMZ | минимум и максимум по всем датчикам |
| Лимит напряжения заряда | настройка шлюза | 56,0–56,8 В (3,50–3,55 В на ячейку) |
| Лимит напряжения разряда | настройка шлюза | 46,4–48,0 В (2,90–3,00 В на ячейку) |
| CCL / DCL | расчёт шлюза | 28,8 А × число исправных модулей, снижение по температуре и по ячейке |
| Флаги charge / discharge enable | расчёт шлюза | снимаются при аварии или потере связи с BMZ |
| Флаг charge immediately | расчёт шлюза | при SOC ниже порога |
Диапазоны лимитов напряжения — предложение для LFP 16S; финальные значения согласовать после теста баланса ячеек.
### 4.4 Справочно: Pylontech CAN V1.3
Нужен, если шлюз будет работать с инверторами, у которых BMS-порт CAN. Параметры: 500 кбит/с, стандартные кадры, период 1 с, инвертор отвечает кадром 0x305 ([спецификация V1.3](https://akkudoktor.net/uploads/short-url/dwFYBPwjnfia9tSuhUopj9uGX2u.pdf)). Основные ID: 0x351 (лимиты напряжения и тока), 0x355 (SOC, SOH), 0x356 (напряжение, ток, температура), 0x359 (защиты, аварии, «PN»), 0x35C (запросы заряда), 0x35E (имя производителя).
## 5. Функциональные требования и безопасность
Главное правило: при любой неопределённости шлюз запрещает заряд и разряд или снижает лимиты, а не сохраняет последние значения.
### 5.1 Функции
| № | Требование |
|---|---|
| F1 | Читать с BMZ напряжение, ток, SOC, 16 напряжений ячеек и температуры не реже 1 раза в секунду |
| F2 | Поддерживать от 1 до 8 модулей BMZ, автоматически находить их по адресу или ID |
| F3 | Отвечать инвертору на все команды из 4.2 не позднее чем через 100 мс после запроса |
| F4 | Рассчитывать CCL и DCL по числу исправных модулей и по температуре |
| F5 | Вести SOC самостоятельно, если BMZ его не передаёт: кулон-счётчик с калибровкой по 100 % при заряде до лимита |
| F6 | Хранить настройки (лимиты, число модулей, ёмкость) в NVS, менять их через веб-интерфейс |
| F7 | Отдавать телеметрию по MQTT и в Home Assistant |
| F8 | Обновляться по воздуху (OTA) |
| F9 | Писать журнал событий: аварии, потери связи, перезагрузки |
### 5.2 Защитная логика
| Условие | Действие шлюза |
|---|---|
| Нет данных от BMZ дольше 10 с | снять флаги заряда и разряда, CCL = DCL = 0 |
| Нет данных от BMZ дольше 60 с | перестать отвечать инвертору, чтобы тот показал ошибку связи |
| Ячейка выше 3,55 В | CCL = 0 |
| Ячейка выше 3,45 В | плавно снижать CCL до 0,1C |
| Ячейка ниже 2,90 В | DCL = 0, поднять флаг charge immediately |
| Температура ниже 0 °C | CCL = 0 |
| Температура выше 45 °C | CCL и DCL снизить вдвое; выше 55 °C — оба 0 |
| Разбаланс ячеек больше 50 мВ | предупреждение 0x44, CCL снизить на верхнем участке заряда |
| Модуль выпал из шины | исключить его из расчёта CCL/DCL |
| Перезагрузка шлюза | до первых свежих данных от BMZ отвечать с CCL = DCL = 0 |
| Watchdog | аппаратный, 5 с |
Пороги по напряжению и температуре — стартовые значения для LFP. Их нужно сверить с порогами встроенной BMS BMZ после реверса, чтобы шлюз срабатывал раньше неё.
### 5.3 Ограничения
- Встроенная BMS BMZ остаётся последним рубежом защиты. Шлюз её не отключает и не перенастраивает.
- Шлюз не должен посылать в шину BMZ ничего, кроме команд, подтверждённых реверсом.
- Настройки инвертора дублируют лимиты: ток заряда в меню не выше 28,8 А × число модулей.
## 6. Программная архитектура и мониторинг
Прошивка пишется на ESP-IDF (актуальная стабильная ветка v5.x) на C/C++, без Arduino и ESPHome. Открытые проекты из раздела 9 используются как справочник по протоколам, а не как зависимости. Компонент Pylontech RS485 от Fahmula (лицензия MIT) переносится на ESP-IDF как эталон логики ответов ([GitHub](https://github.com/Fahmula/esphome-pylontech-rs485)).
### 6.1 Модули прошивки
| Компонент ESP-IDF | Задача | API и основа |
|---|---|---|
| bmz_driver | приём и разбор кадров BMZ, опрос (если нужен), таймауты | `driver/twai.h` для CAN или UART в режиме `UART_MODE_RS485_HALF_DUPLEX` |
| pack_model | сводка по модулям: суммы, минимумы, максимумы, SOC | новый |
| limits | расчёт CCL/DCL и флагов по таблице 5.2 | новый |
| pylon_rs485 | разбор запросов и ответы инвертору | UART RS485 half-duplex, логика по образцу Fahmula |
| storage | настройки и счётчики SOC | `nvs_flash` |
| net | Wi-Fi, веб-интерфейс, MQTT | `esp_wifi`, `esp_http_server`, `esp-mqtt` |
| ota | обновление по воздуху | `esp_https_ota`, две OTA-партиции |
| eventlog | журнал событий | кольцевой буфер в LittleFS |
Ближайший образец по структуре — [topband-bms-gateway](https://github.com/swingstate/topband-bms-gateway/releases/tag/v3.0.0-preview.1) версии 3.0: это модульная прошивка на «родном» ESP-IDF для ESP32-S3, которая мостит BMS по RS485 в CAN-протоколы инверторов. [Battery-Emulator](https://github.com/dalathegreat/Battery-Emulator) написан не на чистом ESP-IDF, но полезен как справочник по протоколам инверторов и логике защит.
### 6.2 Требования к коду
- Сборка через `idf.py`, каждый модуль — отдельный компонент в `components/` со своим `CMakeLists.txt`.
- Драйвер BMZ и ответчик Pylontech — отдельные задачи FreeRTOS с фиксированными приоритетами; обмен через структуру с мьютексом и меткой времени `esp_timer_get_time()`.
- Задачи шины подписаны на task watchdog (`esp_task_wdt`), таймаут 5 с.
- Все масштабы и единицы — константы с комментарием и ссылкой на кадр или страницу спецификации.
- Unit-тесты на Unity (`idf.py -T`) для кодирования кадров Pylontech: контрольные суммы, LENGTH, эталонные кадры из спецификации.
- Настройка через `menuconfig` (Kconfig): GPIO, скорости шин, число модулей по умолчанию.
- Режим «симулятор»: ручные значения вместо данных BMZ, для проверки инвертора без батареи.
- Режим «сниффер»: вывод сырых кадров обеих шин в лог и по MQTT.
### 6.3 Мониторинг
- Веб-страница: напряжение, ток, SOC, ячейки по модулям, текущие CCL/DCL, состояние связи с BMZ и с инвертором.
- MQTT с автообнаружением в Home Assistant.
- Индикация светодиодом: связь с BMZ, связь с инвертором, авария.
- Опционально: чтение самого инвертора по порту Wi-Fi (RS232). SolarAssistant поддерживает SMH III 6.2kW ([SolarAssistant](https://origin.solar-assistant.io/help/inverters/easun?locale=cs)), а для SMG II есть открытая карта регистров Modbus ([easun-smg-ii-11kw](https://github.com/alcestide/easun-smg-ii-11kw)).
## 7. Этапы, тестирование, приёмка
Проект идёт пятью этапами. Каждый заканчивается проверяемым результатом, и следующий не начинается без него.
1. **Разведка батареи.** Распиновка X1/X2, тип шины, скорость, наличие трафика без мастера, логи покоя, заряда и разряда.
   - Результат: отчёт о шине и сырые логи. Решение «реверс возможен / план Б».
2. **Инвертор отдельно.** Эмулятор Pylontech с фиктивными данными, лог запросов SMH III.
   - Результат: значок Li на экране, нет ошибки связи, список CID2, которые опрашивает инвертор.
3. **Протокол BMZ.** Расшифровка кадров, драйвер bmz_driver, сверка с мультиметром и клещами.
   - Результат: погрешность напряжения не более 0,5 %, тока — не более 2 % или 0,5 А.
4. **Интеграция.** Связка драйвера, логики лимитов и ответчика; стендовые тесты на одном модуле при малых токах.
   - Результат: все тесты таблицы ниже пройдены.
5. **Эксплуатация.** 14 дней работы в реальной системе с логированием.
   - Результат: нет зависаний, ни одного срабатывания защиты BMZ раньше шлюза.
### 7.1 Приёмочные испытания
| № | Проверка | Ожидаемый результат |
|---|---|---|
| T1 | Подключение к инвертору, тип LiL | связь за 10 с, значок Li, SOC совпадает с шлюзом |
| T2 | Заряд от солнца или сети | ток не выше CCL; при CCL = 0 заряд прекращается за 5 с |
| T3 | Разряд под нагрузкой | ток не выше DCL; при DCL = 0 инвертор уходит на сеть или выключает выход |
| T4 | Отключение кабеля X1 | через 10 с CCL = DCL = 0, через 60 с инвертор показывает ошибку связи |
| T5 | Отключение кабеля инвертора | шлюз фиксирует потерю опроса в журнале |
| T6 | Имитация ячейки 3,56 В (режим симулятора) | CCL = 0 |
| T7 | Имитация 0 °C | CCL = 0 |
| T8 | Перезагрузка шлюза под нагрузкой | до свежих данных CCL = DCL = 0, затем штатная работа |
| T9 | Выпадение одного модуля из двух | CCL/DCL уменьшились вдвое |
| T10 | 24 ч непрерывной работы | ни одного пропущенного ответа инвертору больше 3 подряд |
Комплект сдачи: исходный код в репозитории, схема и перечень элементов, карта протокола BMZ, инструкция по установке и настройке инвертора, отчёт по тестам T1–T10.
## 8. Совместимость и риски

Если позже понадобится CAN, второй выход по Pylontech CAN V1.3 (раздел 4.4) открывает Deye, Victron (через Cerbo GX), SMA и другие. ### 8.3 Риски
| Риск | Вероятность | Что делаем |
|---|---|---|
| Модуль молчит без мастера, протокол не восстановить | высокая | план Б: заменить штатную BMS на BMS с протоколом Pylontech (так советует [EVcell](https://evcell.com.ua/shop/3kwh-16s16p-57ah-lifepo4-bmz/)) или работать без связи в режиме USE по напряжению |
| Силовые ключи BMZ не включаются без команды мастера | средняя | проверить на этапе 1; без команды включения шлюз бесполезен |
| SMH III опрашивает нестандартные команды | средняя | лог на этапе 2, добавить ответы |
| Ошибки единиц и контрольных сумм в ответах | средняя | unit-тесты, сверка по эталонным кадрам |
| Модули разной ёмкости и износа в параллели | средняя | выравнивать напряжения перед соединением, лимиты по худшему модулю |
| Ток выше 28,8 А на модуль | высокая при 1–2 модулях | CCL/DCL по числу модулей + ограничение в меню инвертора |
| Помехи и разность потенциалов на линиях | средняя | гальваническая развязка обоих интерфейсов |
